# Oddity A 단계: 토대 정리와 공개 준비 설계서

- 날짜: 2026-09-30
- 원 기획서: `Oddity-상세기획서.md` (프로젝트 밖, Codex 출력 폴더)
- 출발점: Codex가 만든 시제품 `solar-cape/` (지구·달·태양, 시험 29개 중 28개 통과)
- 저장소: https://github.com/destory1984/oddity_claude (2026-09-30 현재 비공개, 비어 있음)

## 1. 전체 순서

일을 세 덩이로 나눈다. 덩이마다 설계서 → 작업 계획 → 구현을 따로 거친다.

1. **A. 토대 정리와 공개 준비** (이 문서)
2. B. 태양계 확장: 수성 → 해왕성을 실제 반지름과 1/100 압축 거리로 추가
3. C. 시각 품질: 대기·일출·구름, 태양 코로나, 달 표면, 행성 텍스처, 캐릭터와 망토

B를 C보다 먼저 하는 이유: 행성이 다 놓인 뒤에 텍스처와 대기 효과를 한 번에 입히면 같은 일을 두 번 하지 않는다.

## 2. 도구와 배포

- 빌드: Vite. 개발은 `npm run dev`, 공개용은 `npm run build` 로 `dist/` 생성.
- 엔진: npm `@babylonjs/core` (ES 모듈). 시제품의 7MB `babylon.js` 통짜 파일은 저장소에 넣지 않는다.
- 시험: Vitest. 시제품의 `node:test` 시험을 옮겨 온다.
- 시제품의 `server.cjs`, `start.cmd` 는 쓰지 않는다.
- 배포: GitHub Actions 작업 파일 하나. `main` 에 올리면 빌드 후 GitHub Pages에 게시한다.
  - 주소 `https://destory1984.github.io/oddity_claude/`, Vite `base` 는 `/oddity_claude/`.
  - 무료 계정은 비공개 저장소로 Pages를 열 수 없다. 저장소를 공개로 바꾸고 Pages 설정을 켜는 일은 사용자가 한다. 그 전까지 게시 단계는 실패한다.

## 4. 파일 구조

계산(`core/`)과 그리기(`render/`)를 떼어 놓는다. `core/` 는 Babylon을 가져오지 않으며 전부 시험 대상이다.

```text
index.html
src/
  main.js          시작: 세계 생성, 모듈 연결, 게임 루프
  core/
    bodies.js      천체 표, 압축 배치, 표면 거리
    flight.js      속도 구역, 가속·감속, 연속 충돌(첫 충돌 선택)
    game.js        step(state, input, dt) → { state, events }
    orientation.js 쿼터니언 회전과 방향 벡터
    controls.js    키·터치 → 조작 의도
    pose.js        캐릭터 자세와 관절 제한
  render/
    world.js       엔진, 우주 장면과 캐릭터 장면, 부동 원점
    planets.js     천체 표를 돌며 구체와 재질 생성
    sun.js         태양 원반, 코로나, 가림
    stars.js       별 배경
    hero.js        캐릭터와 망토
    shaders/*.glsl 셰이더 원문 (Vite `?raw` 로 가져옴)
  ui/
    hud.js         숫자, 화면 표지, 오른쪽 패널
    input.js       키보드, 마우스, 터치 스틱, 버튼
    photo.js       사진 모드와 PNG 저장·공유
    toast.js       알림, 같은 문구 반복 방지
public/assets/     텍스처
tests/             Vitest
```

### core/game.js

원 기획서 14장의 프레임 처리 순서를 순수 함수 하나로 옮긴다. 시제품에서는 이 흐름이 `main.js` 루프 안에 있어 시험할 수 없었다.

- 입력: 이전 상태(위치, 방향, 속도, 진행 부호, 감속률, 현재 구역), 조작 의도, 가속 강도, `dt`.
- 출력: 새 상태와 사건 목록. 사건은 `zoneChanged { from, to }`, `surfaceReached { bodyId }`.
- 알림 문구는 `ui/toast.js` 가 사건을 보고 고른다. 문구는 원 기획서 6.3장과 7장 그대로 쓴다.
- 너무 긴 프레임 공백(0.5초 초과)에서 일시 정지하는 판단은 `main.js` 에 남긴다.

코드는 한 줄에 몰아 쓰지 않고 풀어 쓴다.

## 5. 천체 표

`core/bodies.js` 에 천체 하나를 한 줄로 적는다.

| 항목 | 뜻 | 예: 달 |
|---|---|---|
| `id` | 식별자 | `moon` |
| `name` | 한국어 이름 | 달 |
| `radiusKm` | 실제 반지름 | 1737.4 |
| `parent` | 배치 기준 천체 | `earth` |
| `orbitKm` | 기준 천체와의 원래 중심 거리 | 384400 |
| `direction` | 기준 천체에서 본 고정 방향 | 시제품 값 유지 |
| `kind` | `star` / `planet` / `moon` | `moon` |

A 단계의 표에는 태양, 지구, 달만 넣는다.

- 태양이 원점이다. 행성은 태양 기준, 위성은 행성 기준으로 놓는다.
- 중심 거리 = 두 반지름 합 + (원래 중심 거리 − 두 반지름 합) / 100.
- 지구 방향은 시작 장면에서 지구→플레이어 벡터와 지구→태양 벡터가 90도가 되도록 정한다. 시작 위치는 지구 표면에서 9,129km, 시제품과 같은 방향이다.
- 좌표는 km 단위 배정도 수. 해왕성까지 압축해도 약 4,500만 km라 정밀도 문제는 없다. 그릴 때는 플레이어를 원점으로 옮겨 그린다(장면 1단위 = 1,000km).

## 6. 시제품에서 고칠 동작

1. 속도 구역: 100c 구역에서 0.1c 구역으로 곧장 들어갈 때 1c로 붙잡던 예외(`main.js` 의 `activeZone.id==='far'&&nextZone.id==='veryNear'`)를 없앤다. 현재 위치와 이동 선분 중 더 엄격한 구역을 바로 적용한다.
2. 충돌: 지구·달·태양을 따로 검사하던 코드를 표 전체를 도는 함수 하나로 합친다. 이동 선분 위 매개변수 t가 가장 작은 표면을 고른다.
3. 오른쪽 패널: 지구·달·태양 모두 선택, 표면까지 거리, 바라보기가 된다. 화면 표지도 표에서 만든다.
4. 왼쪽 "○○ 상공": 가장 가까운 행성 또는 위성(`kind` 가 `planet`, `moon`)을 보인다.
5. 시제품의 낡은 시험("위성은 실제 거리 384,400km 유지")을 원 기획서대로 압축 거리 검사로 고친다.

그대로 이어받는 것: 가속 3초, 놓으면 1초 선형 감속, 반대 키는 정지 후 반대 가속, Space 즉시 정지, Q/E 롤, 로컬 축 기준 회전, 캐릭터 자세와 관절 제한, 망토 모양, 사진 모드, 모바일 스틱, 포커스를 잃으면 일시 정지.

## 8. 검사

### 자동 검사 (Vitest)

- 표의 모든 천체 쌍에서 압축 중심 거리 > 반지름 합, 표면 사이 빈 거리 = 원래의 1/100
- 시작 시 지구→플레이어와 지구→태양 사이 90도
- 표면 거리 500km, 50,000km 경계에서 구역이 맞는지
- 구역마다 최대 가속 강도로 3초 안에 최고 속도에 닿고 넘지 않는지
- 어느 속도에서든 입력을 놓으면 1초 안에 속도 0
- 한 프레임에 구체를 통째로 지나칠 속도에서도 표면에서 멈추는지
- 여러 천체를 가로지르는 선분에서 첫 충돌을 고르는지
- 100c에서 표면 쪽으로 곧장 가면 0.1c로 바로 낮추고 `zoneChanged` 가 구역마다 한 번만 나오는지
- 표면에 닿은 뒤 바깥쪽으로 바로 출발할 수 있는지
- 지구와 달 중 가까운 쪽으로 "상공" 표시가 바뀌는지
- 쿼터니언을 1만 번 돌려도 길이 1 유지, 팔꿈치가 반대로 꺾이지 않는지(시제품 시험 이어받기)

### 브라우저 직접 검사

- 첫 화면에서 지구가 낮·밤 절반씩 보이는지 (시제품과 스크린샷 비교)
- 지구·달·태양 선택과 바라보기
- 사진 저장 PNG에 HUD가 없는지
- 데스크톱 폭과 375×812에서 버튼이 겹치지 않는지
- 콘솔 오류 0개
- `npm run build` 결과를 `vite preview` 로 띄워 `/oddity_claude/` 경로에서 도는지

## 12. 구현 중 바뀐 점 (2026-09-30)

- 속도 구역 판단: 이동 선분 앞보기 대신, 한 프레임의 이동이 더 엄격한 구역 경계(표면 + 50,000km, + 500km)를 넘으면 그 경계에서 이동을 끊고 속도를 새 제한으로 낮춘다. 앞보기 방식은 100c와 0.1c 사이를 오가며 알림을 반복했다.
- 속도 수치: 사용자 요청으로 별 근처는 느리게, 빈 공간은 빠르게 바꿨다. 표면 근처 0.1c → 0.01c, 별 근처 1c → 0.1c, 빈 공간 100c → 1000c. 별 근처 0.1c에서 지구 지름을 지나는 데 0.4초가 걸린다.
- 1000c가 너무 빠르다는 사용자 의견으로 빈 공간은 다시 100c로 되돌렸다. 별 근처와 표면 근처는 0.1c, 0.01c 그대로다.
- 알림 문구도 새 수치에 맞췄다. 표면에서 멀어져 별 근처 구역으로 올라갈 때는 "별 표면에서 멀어져서, 속도를 광속의 1/10까지 올립니다." 를 쓴다.
